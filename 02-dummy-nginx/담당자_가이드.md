# Nginx 담당자 가이드

모임 전에 이 더미에서 **Nginx Reverse Proxy만** 직접 구성합니다.

Docker는 이미 있습니다. AWS는 하지 마세요.

---

## 당신이 만들어야 하는 것

```text
Nginx Container 추가
Reverse Proxy 설정
upstream 작성
location 작성
proxy_pass 작성
Access Log / Error Log 확인
```

완료 모습:

```text
Browser
   ↓
Nginx :80
   │
   ├─ /       → frontend:3000
   │
   └─ /api/   → backend:4000
```

정상 확인:

```bash
curl localhost
curl localhost/api/health
```

가능하면 Nginx 컨테이너 안에서:

```bash
curl backend:4000/health
```

## 1. nginx.conf 힌트

파일 위치: `nginx/nginx.conf`

```nginx
upstream frontend {
    server frontend:3000;
}

upstream backend {
    server backend:4000;
}

server {
    listen 80;
    server_name _;

    access_log /var/log/nginx/access.log;
    error_log  /var/log/nginx/error.log;

    location / {
        proxy_pass http://frontend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    location /api/ {
        proxy_pass http://backend/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

핵심:

- `location /api/` 의 끝 슬래시와 `proxy_pass`의 끝 슬래시가 경로를 바꿉니다.
- `proxy_pass http://backend/api/;` 이면 브라우저의 `/api/health`가 백엔드의 `/api/health`로 갑니다.
- 컨테이너 이름이 아니라 **compose 서비스 이름** `frontend`, `backend`를 사용합니다.

ALB 헬스체크를 대비해 아래를 추가해도 됩니다.

```nginx
location /health {
    proxy_pass http://backend/health;
}
```

## 2. Nginx Dockerfile 힌트

`nginx/Dockerfile`:

```dockerfile
FROM nginx:1.27-alpine
RUN rm /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

---

## 3. docker-compose.yml에 서비스 추가

기존 파일 **맨 위 서비스 목록에** 추가합니다. 있는 frontend/backend/database는 지우지 마세요.

```yaml
  nginx:
    build: ./nginx
    ports:
      - "80:80"
    depends_on:
      - frontend
      - backend
    networks:
      - app-network
    restart: unless-stopped
```

`networks` 이름이 기존 파일과 같아야 합니다. 이 더미는 compose 키 `app-network`를 사용하고, 실제 네트워크 이름은 `studyboard-nginx-dummy`입니다.

## 5. 확인 명령어

호스트에서:

```bash
curl -i http://localhost
curl -i http://localhost/api/health
curl -i http://localhost/api/posts
```

기대:

- `/` → Next.js HTML
- `/api/health` → `{"status":"ok","service":"studyboard-backend"}`

Nginx 컨테이너 내부에서 Docker Network 통신 확인:

```bash
docker compose exec nginx sh
apk add --no-cache curl
curl -i http://backend:4000/health
curl -i http://frontend:3000
exit
```

로그:

```bash
docker compose logs -f nginx
docker compose exec nginx cat /var/log/nginx/access.log
docker compose exec nginx cat /var/log/nginx/error.log
```

브라우저:

```text
http://localhost
```

아직 프론트는 `http://localhost:4000`으로 API를 호출합니다.
80 포트만으로 완전하게 동작시키려면 프론트 환경변수를 바꿉니다.

## 6. (권장) 프론트를 Nginx 뒤로 붙이기

`frontend/Dockerfile` 빌드 인자와 compose 환경변수를 빈 값으로 바꿉니다.

```yaml
frontend:
  build:
    context: ./frontend
    args:
      NEXT_PUBLIC_API_URL: ""
  environment:
    NEXT_PUBLIC_API_URL: ""
```

그리고 `frontend/app/page.tsx`에서

```ts
const API = process.env.NEXT_PUBLIC_API_URL ?? "";
```

처럼 두고 `/api/health`, `/api/posts`를 호출하게 합니다.

다시 빌드해야 합니다.

```bash
docker compose up -d --build frontend nginx
```

이후 브라우저는 `http://localhost` 만 사용하고, API는 같은 출처의 `/api/...`로 갑니다.

## 자주 나오는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 80 포트 이미 사용 | 로컬 Apache/Nginx 또는 다른 compose | `sudo lsof -i :80` 후 종료 |
| `/api/health`가 404 | location/proxy_pass 슬래시 | `/api/` → `http://backend/api/` |
| 502 Bad Gateway | nginx가 다른 네트워크 | compose `networks` 확인 |
| 502 | frontend/backend가 아직 기동 중 | `depends_on` 후 몇 초 뒤 재시도 |
| 화면은 뜨고 API만 실패 | 프론트가 여전히 localhost:4000 | same-origin 변경 후 재빌드 |

설정 문법 검사:

```bash
docker compose exec nginx nginx -t
```

재시작:

```bash
docker compose restart nginx
```

## 완료 기준

```bash
curl localhost
curl localhost/api/health
docker compose exec nginx curl -s http://backend:4000/health
```

세 명령이 성공하면 Nginx 사전 준비 완료입니다.

모임 당일에는 이 더미가 아니라 **Docker 담당자가 방금 완성한 실제 프로젝트**에 같은 Nginx를 추가합니다.
