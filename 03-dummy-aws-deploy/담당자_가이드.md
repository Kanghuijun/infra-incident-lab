# AWS 배포 담당자 가이드

모임 전에 이 더미를 **EC2 한 대에 직접 배포**해 봅니다.

Docker/Nginx를 다시 만들지 마세요. 이미 있습니다.
ALB/VPC 설계는 Network 담당 숙제입니다. 기본 VPC + 기본 Security Group으로도 이 단계는 완료할 수 있습니다.

---

## 당신이 해야 하는 것

```text
EC2 생성
SSH 접속
Docker 설치
프로젝트 전달
환경변수 확인
docker compose up
EC2 내부에서 서비스 확인
Public IP로 외부 접근 확인
```

완료 모습:

```text
Internet
   ↓
EC2 Public IP
   ↓
EC2 Host :80
   ↓
Nginx Container :80
   ↓
frontend / backend / database
```

## 1. EC2 생성 가이드

콘솔: **EC2 → 인스턴스 시작**

권장 값:

```text
이름: studyboard-dummy
AMI: Ubuntu Server 24.04 LTS
인스턴스 유형: t3.small  (t3.micro는 빌드 중 메모리 부족 가능)
키 페어: 새로 생성 (.pem 보관)
스토리지: 20 GiB gp3
```

네트워크(이 단계 최소):

```text
VPC: default
퍼블릭 IP: 활성화
Security Group:
  - SSH  22   내 IP
  - HTTP 80   내 IP 또는 0.0.0.0/0 (실습용)
```

퍼블릭 IPv4가 할당되었는지 확인하세요.

## 2. SSH 접속

로컬(키 파일이 있는 곳)에서:

```bash
chmod 400 your-key.pem
ssh -i your-key.pem ubuntu@EC2_PUBLIC_IP
```

접속되면:

```bash
uname -a
```

---

## 3. Docker 설치 (Ubuntu)

EC2에서:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
```

그룹 적용을 위해 **SSH를 끊고 다시 접속**합니다.

```bash
exit
ssh -i your-key.pem ubuntu@EC2_PUBLIC_IP
docker version
docker compose version
```

## 4. 프로젝트 전달

방법 A. `scp` (로컬에서 실행):

```bash
# study 저장소 루트에서
scp -i your-key.pem -r 03-dummy-aws-deploy ubuntu@EC2_PUBLIC_IP:~/
```

방법 B. git을 쓰는 경우:

```bash
# EC2에서
git clone <이 저장소 URL>
cd study/03-dummy-aws-deploy
```

방법 C. zip:

```bash
# 로컬
zip -r dummy-aws-deploy.zip 03-dummy-aws-deploy
scp -i your-key.pem dummy-aws-deploy.zip ubuntu@EC2_PUBLIC_IP:~/
# EC2
sudo apt-get install -y unzip
unzip dummy-aws-deploy.zip
```

## 5. 실행

```bash
cd ~/03-dummy-aws-deploy
docker compose up -d --build
docker compose ps
docker compose logs -f
```

첫 빌드는 5~10분 걸릴 수 있습니다. `backend`는 MySQL healthy 이후에 기동됩니다.

문제 시:

```bash
docker compose logs backend
docker compose logs nginx
docker compose logs database
```

## 7. 외부 확인

본인 PC 브라우저:

```text
http://EC2_PUBLIC_IP
```

또는 로컬 터미널:

```bash
curl -i http://EC2_PUBLIC_IP
curl -i http://EC2_PUBLIC_IP/api/health
```

안 되면 점검 순서:

1. `docker compose ps` — nginx가 떠 있는지
2. EC2에서 `curl localhost` — 앱 문제인지
3. Security Group 80 포트 — 네트워크 문제인지
4. 인스턴스 퍼블릭 IP가 맞는지

```bash
curl http://checkip.amazonaws.com
```

## 8. 종료 / 비용

실습이 끝나면 **인스턴스를 중지 또는 종료**하세요.

```bash
docker compose down
```

콘솔에서 인스턴스 중지(stop) / 종료(terminate).

Elastic IP를 할당했다면 그것도 해제합니다.

---

## 자주 나오는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 빌드 중 killed | 메모리 부족 | t3.small 이상, 또는 swap 추가 |
| permission denied docker | docker 그룹 미적용 | 재로그인 |
| 외부에서 안 열림, 내부 curl은 됨 | SG 80 미개방 | 인바운드 규칙 추가 |
| 22 접속 거부 | SG / 키 / 사용자명 | `ubuntu` 사용자, 내 IP SSH |
| 네트워크 이름 충돌 | 로컬 다른 compose | `docker compose down` 후 재실행 |

swap 임시 추가 예 (micro를 써야 할 때):

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

```bash
# EC2 내부
curl localhost
curl localhost/api/health

# 본인 PC
# 브라우저 http://EC2_PUBLIC_IP
```

이 EC2를 Network 담당자가 이어받아 ALB를 붙입니다.
